# 04 · Motor de IA

Todo lo relacionado con la generación de contenido vive en
[`src/lib/ai/`](../src/lib/ai/).

| Fichero | Responsabilidad |
| --- | --- |
| `client.ts` | Cliente de Anthropic, prompt base y bloque de marca |
| `content-types.ts` | Catálogo de formatos: campos e instrucciones |
| `generate.ts` | Orquestación: validar → cuota → llamar → guardar → avisar |

---

## Configuración

```bash
# .env
ANTHROPIC_API_KEY="sk-ant-..."
ANTHROPIC_MODEL="claude-opus-5"
```

La clave se obtiene en la consola de Anthropic. **Sin ella la aplicación arranca
igual**: el generador devuelve un aviso claro y no consume cuota del cliente.

### Por qué `claude-opus-5`

Es el modelo con mejor redacción en español y mejor seguimiento de instrucciones
negativas ("no inventes datos", "no uses estas expresiones"), que es justo de lo
que depende la calidad percibida del producto.

Parámetros de la llamada, en `generate.ts`:

- **`output_config: { effort: 'medium' }`** — para texto comercial, subir a `high`
  no mejora el resultado y encarece la pieza. Merece la pena volver a medirlo si
  cambian las tarifas o el modelo.
- **Razonamiento adaptativo por defecto.** No se desactiva: hacerlo obliga a
  usar un `effort` bajo y puede provocar que el modelo escriba razonamiento
  dentro de la respuesta visible.
- **Streaming siempre.** Aunque no mostremos los tokens en vivo, una petición sin
  streaming con `max_tokens` alto puede agotar el tiempo de espera del SDK.
- **`cache_control` en el bloque base.** Es el texto más largo y se repite en
  todas las peticiones de todos los clientes: es donde el ahorro es mayor.

## Cómo se construye un prompt

Tres capas, en este orden:

1. **`SYSTEM_CORE`** (`client.ts`) — las diez reglas de estilo. Es lo que impide
   que el resultado suene a IA: prohíbe aperturas de relleno, tópicos
   ("sumérgete", "desbloquea"), español neutro y, sobre todo, **inventarse
   datos**. Si falta un dato, el modelo lo marca entre corchetes.
2. **Bloque de marca** — generado desde `BrandProfile`. Solo aparece si el
   cliente ha rellenado algo.
3. **Instrucciones del formato** — de `content-types.ts`, más el tono y la
   longitud pedidos.

> Al cambiar `SYSTEM_CORE` cambias la voz de **todo** el producto. Compara antes y
> después con al menos tres formatos distintos.

## Añadir un formato de contenido

Un único fichero. El formulario, el selector, la validación y el filtro de la
biblioteca se derivan solos.

1. Añade el valor al `enum ContentType` en `prisma/schema.prisma` y ejecuta
   `npm run db:migrate`.
2. Añade la entrada en `CONTENT_TYPES` (`content-types.ts`):

```ts
NEWSLETTER: {
  id: ContentType.NEWSLETTER,
  slug: 'newsletter',              // URL: /app/generar/newsletter
  label: 'Newsletter',
  emoji: '📬',
  description: 'Boletín periódico para tu lista de suscriptores.',
  defaultWords: 600,
  fields: [
    { name: 'topic', label: 'Tema', type: 'text', required: true, maxLength: 160 },
    { name: 'sections', label: 'Secciones', type: 'textarea', maxLength: 1000 },
  ],
  instructions: (i) => `Escribe una newsletter sobre ${i.topic}.
...instrucciones concretas, con estructura obligatoria y límites reales...`,
},
```

3. Añádelo a `CONTENT_TYPE_LIST` en el orden en que quieras que aparezca.

**Cómo escribir buenas instrucciones:** sé concreto con la estructura, indica
límites de caracteres reales cuando existan y termina siempre con las
restricciones ("no inventes plazos de envío", "no uses superlativos absolutos").

## Coste y control

El coste se estima en `estimateCostCents` (`src/lib/plans.ts`) a partir de las
tarifas de Claude Opus 5 y se guarda **en cada generación**. Con eso, `/admin`
muestra el margen real y el coste por cliente.

Tres controles evitan que un cliente dispare el gasto:

1. **Cuota comprobada antes de llamar al modelo.** Es la más importante.
2. **Tope de palabras por plan**, que acota `max_tokens`.
3. **Caché de prompt**, que abarata las peticiones repetidas.

## Errores contemplados

| Situación | Comportamiento |
| --- | --- |
| Falta `ANTHROPIC_API_KEY` | Aviso claro, no se consume cuota |
| Cuota agotada | Mensaje con enlace a facturación, no se llama al modelo |
| `stop_reason: 'refusal'` | Se registra como fallida y se pide reformular |
| Error de red o del proveedor | Se registra la traza, el cliente ve un mensaje genérico |
| Respuesta vacía | Se trata como fallo del proveedor |

Las generaciones fallidas se guardan con `status: FAILED` y **no descuentan
cuota**. Se revisan en `/admin/generaciones`.

## Ideas de mejora

- **Generación por lotes**: subir un CSV de productos y generar todas las fichas.
  Necesita una cola de trabajos, no cabe en una petición HTTP.
- **Regenerar variando el tono** conservando el resto de la entrada.
- **Guardar la mejor versión** con votación del cliente, para afinar los prompts
  con datos reales de preferencia.
